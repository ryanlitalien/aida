aida · system map & gap analysis

system map · 2026-07-20 · UI intentionally excluded

aida: how done is it?

Verdict: the architecture is complete; the remaining work is trust, not construction. Every subsystem you listed exists and is wired end to end. What is missing clusters into five themes: safety rails for autonomy, closing the learning loop into routing, self-observability and cost, multi-device hygiene, and fleet awareness.

30 subcommands 6-step engine, 4 LLM calls 15 source adapters 11 MCP server tools 20+ voice tools 3 repos (code / config / brain) 3 machines running serve

01The flow, end to end

The life of one question, from capture to learned lesson. Amber chips mark the four LLM calls; everything between them is deterministic Go.

1capture
  • 🎙 wake phrase → whisper STT
  • ⌨ terminal · aida "question"
  • 🔌 MCP stdio · HTTP :1610
2understand
  • parse → Intent struct
  • classify · ARI regex, strategy
  • resolve · partners + tokens
LLM ①
3route
  • rank sources · +50 partner
  • lessons apply ±50
  • router picks the subset
LLM ②
4execute
  • per-source query generation
  • parallel fan-out, ≤5 at once
  • snowflake · brave · grep · mcp …
LLM ③
5answer
  • synthesize + citations
  • spoken via Piper on voice
  • run log saved
LLM ④
6learn
  • thumbs up / down / note
  • lessons + Learnings → brain
  • auto-commit → all machines
feedback returns: lessons re-weight routing on the next similar question

03The query pipeline

LLM at the edges, deterministic middle. Amber nodes are LLM calls: there are four, not the three the docs claim (the router was added later; plans/drift-fix-plan.md flags this).

flowchart LR
  Q["question"] --> PARSE["1 · parse → Intent"]
  PARSE --> CLASSIFY["2 · classify · ARI regex + strategy"]
  CLASSIFY --> RESOLVE["3 · resolve · partners, checkout tokens"]
  RESOLVE --> PLAN["4 · plan · rank sources, +50 partner boost"]
  PLAN --> ROUTE["4b · route · pick source subset"]
  ROUTE --> EXECUTE["5 · execute · parallel fan-out ≤5"]
  EXECUTE --> SYNTH["6 · synthesize · cited answer"]
  SYNTH --> OUT["answer + saved run"]
  LESSONS["thumbs-down lessons"] -. "deterministic ±50" .-> ROUTE
  OUT -->|"aida thumbs-up / thumbs-down --because"| LESSONS

04The two loops that make it self-improving

The feedback loop tunes routing and voice behavior from ratings. The autonomy loop drains the task queue with fresh-context agents and distills learnings back into the brain.

flowchart LR
  subgraph FB["feedback loop"]
    TURN["any turn · voice or CLI"] --> RATE["thumbs up / down · note"]
    RATE --> JLESS["jarvis_lessons · embedded"]
    RATE -->|"run-id passthrough"| ELESS["engine lessons"]
    JLESS -. "top-3 recall into next system prompt" .-> TURN
    ELESS -. "router ±50 on next similar query" .-> TURN
  end
  subgraph AL["autonomy loop"]
    TASKS["tasks · 6 statuses"] --> PICK["loop picks highest priority"]
    PICK --> FRESH["fresh agent + brain recall k=3"]
    FRESH --> GATE["--check quality gates"]
    GATE -->|pass| SHIP["done · or PR + review panel"]
    GATE -->|"fail ×3"| PARK["parked on hold"]
    SHIP --> DISTILL["Learnings → brain"]
    DISTILL -. "seeds next similar task" .-> FRESH
  end
